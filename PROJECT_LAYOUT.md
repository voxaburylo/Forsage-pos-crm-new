# Структура Forsage: браузерна CRM і локальна програма

Проєкт лишається одним монорепозиторієм, але розділений за ролями. Це потрібно,
щоб не дублювати касу, товари, замовлення й інші екрани окремо для браузера та
EXE.

```text
apps/
  web/        спільний React-інтерфейс: каса, товари, клієнти, замовлення
  desktop/    локальна Windows-оболонка: EXE, SQLite, bridge, локальна синхронізація
server/       хмарний API, Supabase-синхронізація, віддалені інтеграції
shared/       спільні типи/утиліти для web і server
supabase/     міграції та SQL для хмарної бази
```

## Головне правило

Екрани не дублюємо. Якщо треба змінити касу, замовлення, товари, клієнтів або
інвентаризацію — це майже завжди `apps/web`. Desktop бере готовий web-build і
запускає його всередині EXE.

## Що змінювати де

| Задача | Де змінювати |
| --- | --- |
| Кнопки, форми, таблиці, UX каси/замовлень/товарів | `apps/web` |
| Локальна SQLite, офлайн-продажі, outbox, backup | `apps/desktop` |
| Обмін із Supabase, bootstrap, push/pull sync | `server` + `apps/desktop` |
| Спільні типи або утиліти | `shared` |
| Хмарні таблиці/індекси/RLS | `supabase` |

## Що пушити в GitHub

Пушити:

- вихідний код `apps/web`, `apps/desktop`, `server`, `shared`;
- міграції `supabase`;
- документацію і конфіги збірки.

Не пушити:

- готовий EXE;
- `apps/desktop/release/`;
- `apps/web/dist/`;
- локальні SQLite-бази;
- `.env`, ключі, токени, дампи з паролями;
- тимчасові тестові скрипти з прямими credentials.

Тобто локальна програма як **готовий файл** не йде в GitHub, але її **код**
краще зберігати. Інакше кожна правка локальної каси стане ручною операцією без
історії та контролю.

## Команди

```bash
pnpm dev              # web + server для звичайної розробки
pnpm build            # web + server
pnpm build:web        # тільки браузерний інтерфейс/PWA
pnpm build:server     # тільки сервер
pnpm desktop:smoke    # локальний smoke SQLite без живого UI
pnpm desktop:dist     # зібрати portable EXE
```

Desktop-збірка навмисно відрізняється від PWA-збірки:

- для браузера шляхи ассетів абсолютні `/assets/...`;
- для EXE шляхи локальні `./assets/...`, бо Electron відкриває `index.html`
  через `file://`;
- PWA service worker не включається в EXE, щоб не чіплятися за `/registerSW.js`
  та не ламати локальний запуск.
