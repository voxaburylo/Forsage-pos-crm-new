# Друк етикеток: пошкодження runtime повторним запуском — 25.09.2026

## Підтверджена причина

Користувач повідомив `PRINT_DOCUMENT_LOAD_FAILED` під час друку етикеток.
У чорній скриньці 25.09 перед кожною такою помилкою зафіксовано аварію
print renderer (`crashed`, `-2147483645`), до надсилання принтеру.

У каталозі **працюючої** portable-програми збереглися EXE, завантажені DLL та
`resources/app.asar`, але були відсутні `icudtl.dat`, `resources.pak`, файли
snapshot та `locales`. Основний renderer, завантажений раніше, ще працював;
нові дочірні процеси не могли нормально запуститися.

Причину відтворено окремим EXE без магазинної бази: portable-обгортка
electron-builder 26.15.3 за замовчуванням використовує один тимчасовий каталог
на збірку. Другий запуск завершується через single-instance lock, після чого
його обгортка видаляє незаблоковані ресурси першого запуску. Перевірка
single-instance у JS відбувається надто пізно, щоб захистити цей каталог.

## Виправлення

- `build.portable.unpackDirName: true` активує **окремий `$PLUGINSDIR` на
  запуск** у фактично встановленій реалізації electron-builder 26.15.3.
  Важливо: коментар у його d.ts помилково описує `false`; виконуваний код
  NsisTarget та тест справжнього EXE підтверджують саме `true`.
- Каса та її дані лишаються єдиними: single-instance lock не вимкнений,
  шлях робочої бази не змінено. Тимчасові каталоги створює й прибирає сама
  portable-обгортка; нових встановлень чи ярликів немає.
- Перед запуском renderer друку перевіряються ключові Windows runtime-файли.
  Якщо їх пошкоджено зовнішнім очищенням, повідомлення пропонує зберегти
  роботу та перезапустити програму, а не перевіряти справний USB-принтер.
- Чорна скринька розрізняє `print-runtime-files-missing` та звичайну помилку
  підготовки макета. Шляхи й вміст чеків не потрапляють у повідомлення.
- Розділення POS-58 / POS-80, макет, масштаб, штрихкоди, щільність та
  заборона автоматичного повторного фізичного друку не змінені.

## Перевірки

1. `portable-lifecycle-smoke.cjs --reproduce-old-wrapper`: реальний тестовий
   portable EXE відтворив видалення ICU/resources/snapshot/locales другим запуском.
2. Той самий тест із новими параметрами: два повторні відкриття не видалили
   ресурсів першого запуску; після них підготовлено 1 та 1000 етикеток,
   TSPL-потік у тестовий файл і растровий чек. Фізичні принтери не відкривалися.
3. Повний desktop-набір: 653 тести пройдено; додатковий тест локалізації та
   діагностики після цього — теж пройдено (загалом 654).
4. Typecheck desktop, production build та web ESLint — пройдено.
5. Окремий print-render smoke: віконний/offscreen макет 1/1000/1 етикеток,
   PDF, TSPL dry-run, растровий чек, відновлення renderer після навмисної аварії.
6. Тест життєвого циклу portable EXE доданий у Windows CI.

Робочі залишки, ціни, продажі й документи цим ремонтом не змінювались.
Друк на папері потребує перевірки користувачем після встановлення.
