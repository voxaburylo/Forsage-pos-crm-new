# Forsage — подключение сайта магазина

Инструкция для того, кто делает сайт. Сайт — отдельная программа: он читает каталог и передаёт заказы.
К компьютеру магазина и к самой программе сайт не подключается.

## Доступ

- Адрес: показан в программе, раздел «Сайт» → «Адреса для сайту» (вида `https://…/api/v1/site`).
- Ключ: владелец выдаёт его в том же разделе. Передаётся в заголовке `X-Site-Key`.
- Ключ хранить **только на сервере сайта**. В код страницы (браузер) его класть нельзя.
- Ограничение: 240 запросов в минуту. Ответы — JSON, всё полезное лежит в поле `data`.
- Ошибка: `{ "error": { "code": "...", "message": "...", "status": 409 } }`.
  - `401 SITE_KEY_INVALID` — неверный ключ.
  - `403 SITE_DISABLED` — владелец выключил сайт.

## Деньги и количество

- Цены — целое число **в копейках** (`12500` = 125 грн). Валюта — гривна.
- Цену считает Forsage. Сайт свои цены в заказе не передаёт.
- Закупочные цены, поставщики и клиенты сайту не отдаются.

## Чтение

| Запрос | Что возвращает |
|---|---|
| `GET /info` | Название, телефон, адрес, часы работы, объявление, тексты «о магазине», «доставка», «оплата»; что показывать (`show_prices`, `stock_mode`), принимаются ли заказы, минимальная сумма, `settings_updated_at` |
| `GET /categories` | Разделы каталога: `id`, `parent_id`, `name`, `sort_order` |
| `GET /products` | Товары страницами |
| `GET /products/{id}` | Один товар |

Товар: `id` (постоянный, по нему и связывать), `sku`, `name`, `brand`, `category_id`, `barcode`, `oem_number`,
`unit`, `photo_url`, `updated_at`. Поле `price` есть, только если владелец включил показ цен
(`null` — цена не задана). Наличие — по настройке владельца: нет полей, либо `in_stock`, либо `in_stock` + `qty`.

### Параметры `GET /products`

- `limit` — от 1 до 500 (по умолчанию 200).
- `cursor` — значение `next_cursor` из прошлого ответа. `next_cursor: null` — страниц больше нет.
- `category_id` — только один раздел.
- `updated_since` — время в ISO (`2026-11-24T10:00:00Z`): только карточки, изменённые после него.

### Как держать каталог свежим

1. Первый раз: `GET /products` без `updated_since`, листать по `cursor` до конца. Запомнить время начала загрузки.
2. Дальше раз в несколько минут: `GET /products?updated_since=<то время>`, тоже до конца.
   В таком ответе встречаются записи `{ "id": "...", "removed": true }` — этот товар с сайта убрать.
3. Если в `GET /info` изменилось `settings_updated_at` — владелец поменял настройки (скрыл раздел, изменил
   цены). Тогда каталог загрузить заново целиком, как в шаге 1.

Остатки и цены попадают в облако, когда программа в магазине включена. Ночью они не меняются.

## Заказ

`POST /orders`

```json
{
  "external_id": "S-1042",
  "customer_name": "Іван Петренко",
  "customer_phone": "+380501234567",
  "delivery": "Нова пошта, Київ, відділення 12",
  "comment": "Подзвонити після 18:00",
  "items": [ { "product_id": "…uuid…", "qty": 2 } ]
}
```

- `external_id` — номер заказа на сайте (латиница, цифры, `. _ : -`, до 64 знаков). Повтор с тем же номером
  второй заказ не создаёт, а возвращает первый — запрос можно смело повторять при обрыве связи.
- Телефон — 10–12 цифр (скобки, пробелы и «+» допустимы). До 60 позиций.
- Ответ: `id`, `external_id`, `state`, `order_number`, `items` (с ценой каждой позиции), `total_amount`.
- Отказы (`409`): `SITE_ORDERS_OFF` — приём заказов выключен; `SITE_PRODUCT_UNAVAILABLE` — товара уже нет
  (в `details.product_ids` — какие); `SITE_ORDER_TOO_SMALL` — меньше минимальной суммы.

`GET /orders/{external_id}` — состояние заказа:

| `state` | Значение |
|---|---|
| `waiting` | Ждёт, пока программа в магазине его заберёт (она должна быть включена) |
| `in_program` | Заказ в программе; `order_number` — его номер в магазине |
| `refused` | Программа не приняла заказ — магазину нужно связаться с клиентом |
| `expired` | Программа не забрала заказ за 7 дней |

Оплата через этот адрес не проходит и не отмечается: деньги принимает только касса магазина.
Если на сайте будет онлайн-оплата, это отдельная договорённость с владельцем.
