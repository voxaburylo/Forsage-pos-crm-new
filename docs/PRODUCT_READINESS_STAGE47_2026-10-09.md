# Пакет 47 Узгоджені копії прайсів та перевірка передачі

09.10.2026 у коді виправлено читання й передавання прайсів
постачальників. Позиції, історія та потрібні картки постачальників
читаються одним SQL-запитом. Локальна сторона перевіряє отримані
позиції та історію до запису. Робочу програму ще не оновлено.

## Виправлення

Раніше сторінки прайсу та історія читалися окремими запитами.
Між запитами імпорт міг змінити базу. Один SELECT бачить спільний
стан даних на початок запиту, як визначено в
[документації PostgreSQL](https://www.postgresql.org/docs/current/transaction-iso.html).
Читання тепер використовує наявне серверне підключення PostgreSQL,
без нової функції БД, міграції або розширення прав.

- Початкове копіювання та оновлення довідників читають повний
  прайс з історією, включно з архівними позиціями.
- Звичайне оновлення читає лише зміни після заданої дати.
  Режим і нижня межа явно входять у контрольний опис копії.
  Новіші за основний курсор версії дозволені: наступна передача
  безпечно повторює їх за наявними правилами версій.
- Кількість рядків звіряється з лічильниками того самого запиту.
  Немає незалежного обмеження першою тисячею позицій.
- Контрольна сума SHA-256 зв’язує позиції та історію з магазином,
  курсором і режимом. Пропуск рядка, зміна ціни чи кількості,
  дубль ID, сторонній магазин або пошкоджені метадані блокують
  застосування копії до зміни локальних даних.
- Картки потрібних постачальників беруться з того самого стану
  сервера. Архівний статус зберігається; старий список видалень
  не перекриває пізніше свідоме відновлення картки.
- Кількість у PostgreSQL передається текстом, зі збереженням
  дробової точності; версії зберігають мікросекунди.
- Відсутній ID у копії не є командою видалити локальний запис.
  Локальні невідправлені зміни та старі формати залишаються сумісними.

## Межі гарантії

Контрольна сума перевіряє цілісність передачі, а не правильність
первинної ціни чи фактичного складського залишку. Це не цифровий
підпис і не заміна авторизації. Повнота перевіряється в оголошених
межах: повний прайс або вибірка змін, а не вся база програми.

Старі відповіді без контрольного опису приймаються за попередніми
правилами; вони не дають нового доказу повноти. Інші довідники та
документи ще читаються окремо. Рідкісний пізній COMMIT із давнішою
датою рядка може потребувати повного оновлення довідників; новий
запит такого оновлення вже не обмежує прайс попереднім курсором.

Політика головної локальної бази незмінна. Звичайний вхідний запис
із сервера в desktop IPC залишається заблокованим. Цей пакет
не вмикає автоматичного переписування робочих залишків.

## Перевірки

- Додано 85 desktop і 34 server тести.
- Повний desktop набір: 2080 тестів у 146 файлах.
- Повний server набір: 1752 тести у 98 файлах.
- 41 цільовий web тест перевірив імпорт та локальні повноваження.
  Повний web набір повторно не запускався; у вебкоді змінено лише типи.
- Перевірки типів desktop, server і web, компіляція desktop/server
  та перевірка diff успішні.
- 166 перевірок Electron/SQLite пройшли: 56 нових для контрольного
  опису та 110 попередніх перевірок копіювання.
- Пройшли 18 аварійних сценаріїв та п’ять renderer сценаріїв.
  У renderer журналі є навмисні помилки втрати відповіді та два
  GPU-попередження при закритті ізольованого Electron; усі п’ять
  перевірок завершилися успішно.
- Тестова PostgreSQL повернула понад 2500 рядків без обрізання,
  із перевіркою чужих магазинів та архівних постачальників.
- Локальне застосування 15 000 позицій з перевіркою опису зайняло
  приблизно 1,6 секунди на цьому ПК. Це не гарантія швидкості
  довільної копії та не перевірка граничного розміру HTTP-відповіді.

Перший спільний прогін desktop/server перервався через закритий
канал тестового процесу. Послідовний повтор desktop пройшов.
Застарілий тест структури REST-проєкцій оновлено під спільний
SQL-запит; перевірка потрібних полів збережена.

## Випуск і наступні кроки

Усі бази для перевірок синтетичні. Живий сервер, база магазину,
принтери та другий ПК не використовувалися. Встановлений EXE
не замінено; його SHA-256:
B1399364E4C0F375EB2A0B8E33B8B150A88E1BB45305AF55422FDF6FEE892203.

Пакети 34–47 ще не встановлені й не опубліковані. Дві попередні
серверні міграції залишаються незастосованими; нових немає.
Перед випуском залишаються перевірка великих мережевих копій
і меж розміру відповіді, усунення блокування основного потоку,
строга домовленість про версію протоколу при майбутньому вмиканні
вхідного копіювання та перенесення прайсів з історією при
об’єднанні постачальників. Злиття з непідтриманими залежностями
залишається заблокованим.
