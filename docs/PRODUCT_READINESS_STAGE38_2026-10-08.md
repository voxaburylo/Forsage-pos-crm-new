# Пакет 38 Повнота збереження оплат постачальникам

08.10.2026 посилено доплати до накладних і копіювання цих оплат на сервер.
Успіх підтверджується лише після перевірки фактичної оплати, оплаченої суми,
касового руху та локальної черги. Неповна спроба відкочується цілком.
Нових кнопок і функцій немає.

## Відтворені проблеми

Перші 18 нових перевірок відтворили удаваний успіх на ізольованих SQLite
і PostgreSQL базах. Тестові тригери пропускали запис без звичайної помилки
або змінювали дані під час збереження. Старий код міг прийняти таку оплату.

Перевірялися пропущені оплати, оновлення оплаченої суми, касові записи
та черга; підміна суми, примітки, кількості й закупівлі при незмінному
підсумку. Це імітація збоїв для перевірки захисту, а не встановлена
причина попередніх розбіжностей магазину.

## Виправлення

- Доплата перевіряє кількість записаних рядків і перечитує результат
  до завершення транзакції. Накладна, попередні платежі й товарні рядки
  не можуть непомітно змінитися.
- Черга передачі перевіряється за ID, документом, пристроєм, станом,
  датою та повним вмістом. Її відсутність скасовує нову доплату.
- Повтор локального платежу звіряє накладну й відповідний касовий рух.
  Пошкоджена історія не видається за успіх і автоматично не переписується.
- Дві однакові готівкові оплати в одну мить потребують двох касових записів.
  Для давніх локальних записів з незалежними ID перевіряються сума,
  постачальник, зміна, платник, дата, примітка та кількість збігів.
- Оплата під час створення накладної також перевіряє запис платежу й каси,
  включно зі зміною цих записів після додавання черги.
- Власні кошти, банківський рахунок і бізнес-картка не зменшують готівку каси.
- Сервер копіює вже виконаний платіж з первісними платником і датою.
  Закрита зміна не перетворює повтор на нове списання. Урахований реальний
  серверний тригер часу оновлення; порядок блокувань збережено.

## Перевірки

Додано 42 автоматичні тести: 29 локальних і 13 серверних.

- Повний локальний набір: 1559 тестів у 137 файлах, усі успішні.
- Повний серверний набір: 1704 тести у 97 файлах, усі успішні.
- Разом 3263 успішні тести; окремий серверний файл накладних містить 361 тест.
- Перевірки типів desktop, server та API пройшли.
- Компіляція desktop і server успішна.
- Зібраний код під Electron пройшов 45 перевірок оплат, а також повторні
  46 перевірок об’єднання постачальників і 18 перевірок прайсів.
- Перевірено повтор після перезапуску, закритої зміни й очищення черги,
  повний відкат і наступну успішну спробу, незмінність товарних залишків.
- Перевірка змін Git не виявила помилок форматування.

Electron перевіряв зібраний dist на синтетичних даних, не новий упакований
EXE. Фізичні принтери, відключення живлення й два ПК у цей пакет не входять.

## Стан встановлення

Пакети 34–38 залишаються у коді, без встановлення й публікації.
Робочу базу для тестів не відкривали, реальних оплат не створювали.
Наявний EXE 20261007T052142-d87b0051d797 незмінний; перевірений SHA256:
B1399364E4C0F375EB2A0B8E33B8B150A88E1BB45305AF55422FDF6FEE892203.

Пакет 38 не змінює схему. Дві міграції пакетів 35 і 36 ще потрібно
застосувати перед публікацією поточного серверного коду.

## Наступні кроки

1. Продовжити перевірку повноти початкового запису накладної: заголовок,
   усі товарні рядки й черга. Поточний пакет посилив її платіж,
   але не замінює окремого аудиту всього створення документа.
2. Завершити незмінний знімок прайсів та історії імпортів для об’єднання
   постачальників. Непідтримані залежності досі блокують часткове злиття.
3. Звірити давню чергу та історичні розбіжності без автоматичної зміни даних.
4. Підготувати узгоджений випуск з міграціями, свіжим резервом,
   перевіркою відновлення й заміною одного EXE після закриття програми.
