> 2026-06-11. Мета: «найкраща система, якою я користувався» очима власника магазину,
> і готовність продаватись іншим магазинам як SaaS через місяць.
> Не баги (їх закрито в AUDIT.md / PRODUCT_ROADMAP.md) — досвід і цінність.

## Аудит за сценаріями

### Перший запуск (нового магазину) — 🔴 головна прогалина для SaaS
Зараз: порожня система, налаштування руками по 4+ розділах, користувачів створює
розробник через seed/admin. Власник без супроводу не запуститься.
Потрібно: майстер онбордингу «магазин за 15 хвилин» (назва → ПРРО/термінал (можна
«потім») → перший співробітник → імпорт прайсу → перший продаж).

### Навчання нового співробітника — 🟡 прийнятно
Ролі ховають зайве (касир бачить касу), у POS є довідка гарячих клавіш (F1) і
підказки. Немає вбудованого туру перших кроків. Для SaaS вистачить короткої
PDF/відео-інструкції на роль (1 день роботи, без коду).

### Робочий день касира — ✅ сильно
Зміна → сканер/пошук (trgm, F4) → чек (знижки, бонуси, борг, застава, відкладені
чеки) → оплата (готівка/карта/термінал/змішана, ідемпотентність) → видача замовлень →
закриття зміни зі звіркою одним вікном. Конкурентний рівень.

### 1 млн товарів — ✅ ядро готове / 🟡 імпорт
Пошук по GIN trgm-індексах, серверна пагінація, ліміти. Вузьке місце: імпорт великих
прайсів іде з браузера батчами — на 1М рядків це години та відкрита вкладка.
Потрібно: серверний імпорт-воркер (інфраструктура jobs/BullMQ вже є) з прогресом.

### Директор магазину — 🟡 дані є, «пульсу» немає
Аналітика широка (P&L, ABC, KPI, прогноз, аномалії), але директор має сам ходити
по вкладках. Бракує ранкової зведенки: вчорашня виручка/маржа/каса/борги/зависші
замовлення — одним повідомленням у Telegram. Інфраструктура бота вже є.

### Закупник — 🟡 цикл замкнуто сьогодні, бракує «мозку»
Авто-PO тепер видимі (/suppliers/pos), автозакупки і «Мало товару» є. Бракує
порівняння цін постачальників по позиції (дані вже є: product_supplier_codes +
історія закупівель) — «у кого дешевше» прямо в PO/накладній.

### Менеджер з продажу — ✅ добре
Замовлення за хвилину (каталог, VIN, аналоги по тірах, інлайн-клієнт), чати Telegram,
нагадування про дедлайни видачі, листи очікування з авто-сповіщеннями.

### Масштабування на мережу магазинів — 🔴 блокер SaaS, але ближче ніж здавалось
Вже готово: tenant_id ОБОВ'ЯЗКОВИЙ у JWT (фолбек прибрано), всі запити фільтрують
tenant, RLS на таблицях, ролі.
Лишилось: (1) глобальні sequence номерів чеків/замовлень/PO — наскрізні між
tenant'ами (фіскально неприйнятно) → per-tenant лічильники; (2) DB DEFAULT
'000...001' на tenant_id — прибрати; (3) Telegram-бот один на процес → менеджер
ботів per tenant; (4) реєстрація магазину + білінг (LiqPay/Stripe підписка);
(5) ізоляційні тести (PGlite-набір уже є — розширити cross-tenant кейсами).
Оцінка: 2–3 тижні сфокусованої роботи.

### Конкурентні переваги (що вже краще за ринок)
Core exchange (застава за серцевини, борги в обидва боки), аналоги по тірах брендів,
VIN-підбір, авто-PO із замовлень, продажі через Telegram, ПРРО+термінал з коробки,
офлайн-PWA каса, друк етикеток/пікінгів, аудит-лог дій.

## Порядок із максимальним ROI

**Тиждень 1 (швидкі перемоги для діючого магазину):** №1 дайджест → №2 Viber
(потрібен токен) → №5 SMS → №3 порівняння цін.
**Тиждень 2:** №4 Нова Пошта → №6 імпорт-воркер.
**Тижні 3–4 (підготовка до продажу):** №7 онбординг → №8 мультимагазин (паралельно №9, №10 за часом).
