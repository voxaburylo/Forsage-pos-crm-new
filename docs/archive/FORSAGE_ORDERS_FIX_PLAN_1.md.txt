# Forsage CRM — План доопрацювання модуля «Замовлення»

> **Для ШІ-кодера.** Це план робіт. Рухайся зверху вниз: спочатку блок CRITICAL, потім HIGH, потім MEDIUM, потім LOW.
> Кожне завдання має формат: **Зараз** (поточна поведінка) → **Зробити** (що реалізувати) → **Готово коли** (критерій приймання).
> Не змінюй пункти, позначені ✅ KEEP — це вдалі рішення, їх треба зберегти й не зламати при рефакторингу.
> Працюй ітеративно: одне завдання = один коміт із префіксом `[ORD-N]`. Після кожного блоку — переконайся, що нічого з ✅ KEEP не зламано.

**Контекст продукту:** CRM для магазину автозапчастин (POS). Головний користувач — менеджер, який весь день оформлює замовлення. Цілі: більше замовлень за той самий час, менше кліків, менше відкритих сторінок, менше забутих клієнтів, швидша робота з повторними клієнтами.

**Стек/середовище:** веб-застосунок (Next.js на Vercel за URL). Працює і на десктопі, і на мобільному. **Мобільна адаптація — слабка, це наскрізна проблема.**

---

## ✅ KEEP — зберегти й не ламати

Ці рішення вдалі. При рефакторингу переконайся, що вони продовжують працювати.

- **K1.** Пошук клієнта в одному полі одночасно по «Ім'я / Телефон / VIN».
- **K2.** VIN зберігається за автомобілем, не вводиться щоразу, і тягнеться в підтвердження замовлення.
- **K3.** Кнопка «Зберегти як чернетку» поряд з «Оформити замовлення».
- **K4.** Мітка «🔥 ТЕРМІНОВО (позначити замовлення червоним)».
- **K5.** Способи передоплати (Готівка / Картка / Переказ) + чекбокс «Фіскалізувати передоплату (ПРРО)».
- **K6.** Блок «Оплати» на картці замовлення (Дата / Сума / Метод / ПРРО + «Додати оплату»).
- **K7.** «Журнал дій» на картці замовлення.

## 🔴 CRITICAL — найбільший приріст швидкості

### [ORD-1] Пошук товару по каталогу замість ручного вводу
- **Зараз:** на кроці 3 (Специфікація) поля «Назва запчастини», «Артикул/SKU», «Ціна» заповнюються вручну текстом. Ціна за замовчуванням `0`. Немає автопідказки, немає підтяжки ціни й залишку.
- **Зробити:** поле назви/артикула зробити автокомплітом по товарній базі. Користувач друкує → випадають збіги (назва, артикул, ціна, залишок на складі) → вибір підставляє SKU і ціну автоматично. Ручний ввід лишити як запасний варіант для робіт/разових позицій.
- **Готово коли:** додавання позиції з каталогу займає ≤2 дії (друк + вибір), ціна й SKU підставляються самі, видно залишок.

### [ORD-2] «Повторити замовлення»
- **Зараз:** повторне замовлення оформлюється з нуля через усі 4 кроки. Кнопки повтору немає ні в картці клієнта, ні в рядку старого замовлення.
- **Зробити:** кнопку «Повторити замовлення» в картці клієнта та в дії над існуючим замовленням. Створює нове замовлення з тим самим клієнтом, авто і позиціями; лишається тільки підтвердити/відредагувати.
- **Готово коли:** повтор створює чернетку/замовлення в ≤2 кліки, усі позиції й авто перенесені.

### [ORD-3] Скоротити 4-кроковий майстер
- **Зараз:** створення = 4 окремі екрани (Клієнт → Авто → Товари → Оплата) з «Далі» між кожним. Для повторного клієнта більшість кроків зайві.
- **Зробити:**
  - Десктоп: усе на одному екрані (клієнт, авто, товари, оплата — секціями).
  - Мобільний: лишити кроки, але додати «швидкий режим» — для існуючого клієнта з одним авто одразу відкривати крок товарів.
- **Готово коли:** на десктопі замовлення оформлюється без перемикання екранів; на мобільному для повторного клієнта пропускаються кроки 1-2.

## 🟠 HIGH — щоденний біль і помилки

### [ORD-4] Автопропуск кроку вибору авто, якщо машина одна
- **Зараз:** крок 2 «Оберіть автомобіль» показується завжди, навіть коли в клієнта єдине авто (його все одно треба тапнути + «Далі»).
- **Зробити:** якщо в клієнта одне авто — підставляти автоматично і пропускати крок; показати авто на кроці товарів з можливістю змінити. Окремий екран лишити тільки коли авто кілька або немає.
- **Готово коли:** клієнт з одним авто не бачить окремого екрана вибору.

### [ORD-5] Підтяжка ціни + валідація нульової суми
- **Зараз:** ціна `0` за замовчуванням; замовлення з сумою `0,00 ₴` проходить далі без попередження.
- **Зробити:** ціна підтягується з каталогу (залежить від ORD-1). Перед «Далі»/«Оформити» — валідація: якщо сума = 0, показати попередження й не давати оформити без підтвердження.
- **Готово коли:** не можна випадково оформити замовлення на 0 грн.

### [ORD-6] Попередження при передоплаті, більшій за суму
- **Зараз:** сума 450 ₴, можна внести передоплату 2000 ₴ — система приймає мовчки, решта ніде не фіксується.
- **Зробити:** якщо передоплата > суми до сплати — показати «Решта: X ₴» і поле/логіку решти, або обмежити ввід. Зафіксувати решту в оплатах.
- **Готово коли:** переплата явно показана як решта, каса не «з'їдає» різницю мовчки.

### [ORD-7] Повернути видачу товару в мобільний режим
- **Зараз:** на касі (десктоп) видача працює: пошук за кодом / телефоном / VIN → відпуск через касу. У мобільному режимі кнопка/блок видачі **зник** — це баг адаптації, не відсутність функції.
- **Зробити:** повернути блок видачі в мобільну верстку з тією ж логікою (пошук → знайти → «Видати»).
- **Готово коли:** з телефона можна знайти замовлення за кодом/телефоном/VIN і видати товар.

### [ORD-8] Людський номер замовлення замість хеша
- **Зараз:** замовлення ідентифікується хешем (напр. `#b5c544b0`) — не запам'ятати, не продиктувати, не знайти голосом.
- **Зробити:** показувати людський порядковий номер (напр. `#1043`). Технічний хеш лишити в БД, в UI показувати номер. Пошук має працювати за людським номером.
- **Готово коли:** у списку, картці та пошуку фігурує короткий порядковий номер.

### [ORD-9] Інформативний рядок у списку замовлень
- **Зараз:** рядок показує клієнт / авто / сума / борг. Немає статусу, складу замовлення, передоплати. Будь-яка перевірка стану = відкрити картку.
- **Зробити:** додати в рядок кольоровий бейдж статусу, першу позицію товару (або «N позицій»), та «Сплачено X / Борг Y».
- **Готово коли:** 60-70% питань про замовлення вирішуються без відкриття картки.

### [ORD-10] Передоплата/борг у списку (а не лише «Борг»)
- **Зараз:** у списку видно лише `Борг: 1500`, не видно скільки внесено.
- **Зробити:** показувати «Сплачено X / Борг Y». (Може бути частиною ORD-9.)
- **Готово коли:** платіжний стан зрозумілий зі списку.

### [ORD-11] Заповнювати колонку «Авто» в списку
- **Зараз:** колонка «Авто» в списку порожня (прочерк), хоча авто є в картці.
- **Зробити:** підтягувати авто з картки клієнта/замовлення. Якщо авто реально немає — не показувати мертвий прочерк.
- **Готово коли:** авто видно у списку для замовлень, де воно є.

### [ORD-12] Картковий layout списку на мобільному
- **Зараз:** таблиця ламається на телефоні: колонки Сума/Статус за краєм екрана, горизонтальний скрол, текст переноситься в 3 рядки.
- **Зробити:** на мобільному замість таблиці — картки (одне замовлення = одна картка, дані в стовпчик). Таблицю лишити на десктопі.
- **Готово коли:** на телефоні немає горизонтального скролу, все видно одразу.

### [ORD-13] Полагодити шапку картки замовлення на мобільному
- **Зараз:** «Замовлення від…», кнопка «Зібрати», «Дії» налазять одне на одне під адресним рядком браузера.
- **Зробити:** виправити мобільну верстку шапки (перенос/стиснення/меню дій).
- **Готово коли:** заголовок і кнопки не перекриваються на мобільному.

### [ORD-14] Автонагадування з листа очікування при надходженні товару
- **Зараз:** «Лист очікування» — окрема вкладка, не зв'язана з надходженнями. Коли товар приходить, нагадування подзвонити клієнту немає.
- **Зробити:** при оприбуткуванні товару, який хтось чекає, — автонагадування менеджеру (і опційно клієнту) по всіх, хто його очікував.
- **Готово коли:** надходження очікуваного товару створює нагадування.

### [ORD-15] Нагадування про незабрані товари
- **Зараз:** механізму нагадати про товар, що прийшов, але клієнт не забрав, немає.
- **Зробити:** автонагадування менеджеру через N днів після готовності до видачі (N — налаштовуване).
- **Готово коли:** незабрані товари спливають у нагадуваннях.

### [ORD-16] Зведений список боргів клієнтів
- **Зараз:** борг видно тільки на окремому замовленні; єдиного переліку боржників немає.
- **Зробити:** розділ/фільтр «Борги» зі списком клієнтів, сумою боргу й кнопкою «нагадати».
- **Готово коли:** видно всіх боржників в одному місці.

### [ORD-17] Наскрізний прохід по мобільній адаптації
- **Зараз:** загалом логіка та сама, але розміри під мобільний підігнані погано (обрізані кнопки, налазить шапка, скрол таблиць, зникла видача).
- **Зробити:** окрема задача-ревізія мобільної верстки всього модуля (після точкових фіксів ORD-7, ORD-12, ORD-13).
- **Готово коли:** усі екрани модуля коректно виглядають на ширині телефону.

## 🟡 MEDIUM — зручність і чистота даних

### [ORD-18] Кольорові статуси позицій замовлення
- **Зараз:** статус позиції читається погано («Шарова | Епа | Очікує»), тег обрізаний.
- **Зробити:** кольорові статуси позицій: Очікує / Замовлено постачальнику / Прийшло / Видано. Помістити обрізані теги.
- **Готово коли:** етап кожної позиції зрозумілий з першого погляду.

### [ORD-19] Зв'язати кнопку «Замовлено» з листом очікування й постачальником
- **Зараз:** на позиції є кнопки «Етикетка / Замовлено / Скасувати». Незрозуміло, чи «Замовлено» створює запис у листі очікування й тригерить нагадування.
- **Зробити:** «Замовлено» → позиція потрапляє в лист очікування / замовлення постачальнику → при надходженні спрацьовує ORD-14.
- **Готово коли:** ланцюг «замовив постачальнику → прийшло → нагадування клієнту» працює наскрізно.

### [ORD-20] Явний крок «Замовити постачальнику»
- **Зараз:** окремого видимого модуля замовлень постачальнику немає; «Замовлено» — єдиний натяк.
- **Зробити:** з позиції зі статусом «Очікує» — дія «Замовити постачальнику», що веде в лист очікування.
- **Готово коли:** є зрозумілий шлях оформити дозамовлення.

### [ORD-21] Знижка з перемикачем ₴ / %
- **Зараз:** «Знижка на замовлення (грн)» — лише сума, % рахується вручну.
- **Зробити:** перемикач ₴ / %. Ввід `10%` → авторозрахунок.
- **Готово коли:** знижку можна задати у відсотках.

### [ORD-22] Швидкі дії оплати
- **Зараз:** «Знижка 0» і «Передоплата 0» вводяться вручну, швидких кнопок немає.
- **Зробити:** кнопка «Сплатити повністю» (підставляє суму до сплати), швидкі суми (50% / повна).
- **Готово коли:** повну оплату можна внести одним тапом.

### [ORD-23] Контекст у рядку пошуку клієнта
- **Зараз:** рядок клієнта показує лише ім'я, телефон, «Авто / Немає авто».
- **Зробити:** додати борг (червоним), кількість замовлень, останнє авто.
- **Готово коли:** статус клієнта (боржник/постійник) видно без відкриття картки.

### [ORD-24] Тип позиції: товар / робота
- **Зараз:** колонка зветься «Назва запчастини/роботи», але типу немає; впливає на склад і фіскалізацію.
- **Зробити:** позначка типу позиції (товар / робота).
- **Готово коли:** позиції розрізняються за типом.

### [ORD-25] Єдиний огляд «Потребує дії»
- **Зараз:** Чернетки, Месенджер-ліди, Лист очікування рознесені по вкладках — усе це «недотиснуті продажі».
- **Зробити:** зведений екран/віджет «Потребує дії»: борги + незабрані + лист очікування + чернетки.
- **Готово коли:** менеджер бачить усе, що вимагає дії, в одному місці.

### [ORD-26] Лічильники-бейджі на всіх вкладках
- **Зараз:** бейджі є на «Месенджер 3», «Ліди 4», але немає на «Чернетки» й «Лист очікування».
- **Зробити:** бейджі-лічильники на всіх вкладках.
- **Готово коли:** не треба заходити у вкладку, щоб дізнатись, чи там порожньо.

### [ORD-27] Дублі замовлень
- **Зараз:** два замовлення з тим самим клієнтом, часом, сумою й боргом у списку не відрізнити.
- **Зробити:** показувати товар/статус як ознаку + попередження про можливий дубль при створенні (той самий клієнт+сума у короткий проміжок).
- **Готово коли:** дублі видно й система попереджає про них.

### [ORD-28] Прив'язка чатів Месенджера до замовлень
- **Зараз:** вкладка показує чати, але не видно, чи прив'язані вони до замовлення.
- **Зробити:** позначка «є замовлення / лід без замовлення» + кнопка «створити замовлення з чату».
- **Готово коли:** з чату можна одразу створити замовлення.

### [ORD-29] Підбір запчастин по VIN
- **Зараз:** VIN зберігається (✅ K2), але по ньому не можна шукати деталі — це просто текст.
- **Зробити:** кнопка «підібрати по VIN» / передача VIN у пошук каталогу (залежить від ORD-1).
- **Готово коли:** VIN можна використати для підбору позицій.

## 🟢 LOW — дрібні покращення

### [ORD-30] Один порожній рядок товару за замовчуванням
- **Зараз:** на кроці 3 одразу два порожні рядки.
- **Зробити:** один рядок; новий додається по кнопці або коли попередній заповнено.

### [ORD-31] Помістити обрізані «Пропустити вибір…»
- **Зараз:** «Пропустити вибір клієнта (Швидке…)» обрізане; швидкий режим виглядає другорядним.
- **Зробити:** помістити текст; підняти швидкий режим як рівноцінну опцію.

### [ORD-32] Рік авто на кроці вибору
- **Зараз:** на картці рік є (2012), на кроці вибору авто — ні.
- **Зробити:** показувати рік і на кроці вибору, щоб не плутати однакові моделі.

### [ORD-33] Сортування клієнтів (нещодавні/часті зверху)
- **Зараз:** список клієнтів без явного порядку.
- **Зробити:** нещодавні/часті клієнти зверху.

### [ORD-34] Швидкі теги коментаря
- **Зараз:** коментар — лише вільний текст.
- **Зробити:** швидкі теги (передзвонити / самовивіз / потрібна накладна) на додачу до тексту.

### [ORD-35] Гарячі клавіші на десктопі
- **Зараз:** усе мишкою.
- **Зробити:** Enter — новий рядок товару, Ctrl+S — зберегти, тощо.

### [ORD-36] Шаблони частих позицій
- **Зараз:** типові набори (ТО, фільтри по моделі) вводяться щоразу з нуля.
- **Зробити:** шаблони/набори позицій, що додаються одним тапом.

## Порядок виконання (рекомендований)

1. **CRITICAL** (ORD-1 → ORD-3) — дають найбільший приріст швидкості. ORD-1 розблоковує ORD-5 і ORD-29.
2. **HIGH** (ORD-4 → ORD-17) — щоденні болі; ORD-7/12/13 закрити до загального ORD-17.
3. **MEDIUM** (ORD-18 → ORD-29) — зв'язність процесів і зручність.
4. **LOW** (ORD-30 → ORD-36) — полірування.

**Правила роботи:** один пункт = один коміт `[ORD-N] короткий опис`. Не ламати ✅ KEEP. Після кожного блоку — швидка перевірка, що флоу «створити → оплатити → видати → повторити» працює наскрізно.
