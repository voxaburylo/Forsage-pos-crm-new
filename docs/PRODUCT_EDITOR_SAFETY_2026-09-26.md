# Картка товару: збереження й довідники — 26.09.2026

## Відтворення

У справжній React-формі два submit-повідомлення до наступного render
викликали два productApi.update. Регресійний UI-тест до виправлення впав:
очікував один запис, отримав два. Перевірка React-state saving не була
синхронним блокуванням дії.

Поряд виявлені запізніла генерація штрихкоду без захисту ручного вводу,
відсутність актуальності результату save після переходу до іншого товару,
повторне створення категорії/бренду, мовчазна помилка читання довідників
і різні способи розбору ціни при розрахунку націнки та збереженні.

## Виправлено

- Один синхронний ActionScope на збереження й створення категорії/бренду.
  Під час запису поля й скасування заблоковані. Старий результат після
  переходу не закриває іншу картку і не показує їй повідомлень.
- Окремі контексти для генерації штрихкоду та націнки. Ручний ввід
  скасовує актуальність старої підказки, повторний виклик не дублюється.
  Збереження чекає активного розрахунку/генерації/додавання фото.
- Ціни перевіряються цілком одним строгим розбором до запису.
  Поля приймають кому й пробіли тисяч, наприклад 1 250,50.
  Попередження про від'ємну націнку теж порівнює повні точні суми.
  Некоректна/дробова в копійках/занадто велика підказка ціни відхиляється.
- Чистий productFormModel перевіряє SKU, назву, ціни, мінімальний залишок;
  зберігає початкові нулі штрихкоду, не змінює вихідний об'єкт форми.
  Спостережений qty_on_hand не передається з редактора. Прихована
  закупівельна ціна не надсилається касиром/менеджером.
- Довідники повинні завантажитися перед збереженням. Помилка має явний
  стан і повтор лише читання. Після невизначеного результату створення
  категорії/бренду потрібно перечитати довідники, а не повторювати запис.
- Тип ProductCreateData дозволяє відсутність stock/purchase без any-cast.
  Семантика локального API та права/схема бази не змінювалися.

## Перевірки

- 838 web + 739 desktop = 1577 успішних тестів; 1 optional XLSX пропущено.
- 42 нові перевірки моделі і 5 перевірок реального productApi з фіктивним
  локальним мостом: точні копійки, новий товар із нулем, актуальний залишок
  замість старого, прихована закупівля, помилка без fallback/retry в інтернет,
  звільнення черги після помилки.
- Розширено product-photo-ui-smoke.mjs: подвійні update/create, pending
  контролі, помилка/повтор, перехід A→B, штрихкод/ручний ввід, розрахунок
  націнки й ручна ціна, create category/brand, непевний результат, невдале
  читання/повтор, збереження касиром. Попередні сценарії фото теж пройдено.
- Catalog-edit та AI-supply UI пройдені. TypeScript, ESLint, production
  build і перевірка app.asar пройдені.
- Electron file:// Excel worker і packaged AI worker (15000 товарів,
  100 нових рядків, повтор без дублювання, rollback) пройдені.
- Print dry run: 1/1000/1 етикеток, receipt raster, TSPL та відновлення
  renderer пройдені. Реальним принтерам завдання не надсилалися.
