# Пакет 11 — надійність наявного екрана статистики

Дата: 03.10.2026. Статус: код, автоматичні перевірки й збірка готові. EXE підготовлено у службовому release/staged, але не встановлено: робочий «Форсаж» відкритий. Публікації GitHub/Vercel не було.

## Виправлення

- Серверний dashboard тепер віднімає завершені повернення за датою повернення, зокрема за попередні продажі та у дні без нових чеків.
- Собівартість береться з початкового sale_items.cost_price. Нульова зафіксована ціна більше не підміняється поточною ціною товарної картки. Це не відновлює невідому історичну закупівлю і не змінює старі записи.
- Собівартість сторнується тільки за return_to_stock. Для write_off/send_to_supplier повернення грошей не означає повернення товару на склад.
- Загальна сума повернення береться один раз із документа, незалежно від кількості його рядків. Старий refund_amount використовується лише коли refund_kopecks відсутній, а не коли він явно нульовий.
- Відсутній зв'язок наявного рядка повернення з первинним рядком продажу дає помилку неповного звіту, а не вигадану нульову собівартість.
- Календарні дати й порядок початку/кінця перевіряються до читання бази. Межі дня — Europe/Kyiv, верхня межа виключна; перевірені зимовий, літній і обидва перехідні дні.
- Статистика продажів, повернень, витрат, залишків і боргів читається одним SQL-запитом з одного знімка бази. Немає обмеження першою REST-сторінкою.
- Денні значення прибутку також приховані в серверній відповіді для ролей без права бачити прибуток. Це виправлення конкретного dashboard API, не твердження про завершений аудит усіх локальних/веб прав.
- Екран не показує нулі при відмові завантаження чи неповній відповіді. Дані шиномонтажу мають окремі стани завантаження/помилки; відсутні суми не видаються за нульову зарплату.
- Вилучено старий неповний запасний розрахунок у браузері через списки чеків, перші 500 замовлень і перші 200 боржників. Старий локальний міст без повного звіту просить оновлення, а не показує частковий або серверний результат замість локального.
- Після вибору іншої дати картка більше не називає її «сьогодні». Пізній результат старого запиту не підміняє новий період.

Нових кнопок/модулів не додано. Локальні складські розрахунки та документи не змінювалися; веб лишається read-only. Бонуси, кешбек, старі залишки й історичні гроші не переписувалися.

## Докази

Новий серверний набір analyticsDashboard.test.ts запускає реальний обробник і його SQL на ізольованому PostgreSQL-сумісному PGlite, а не імітує результат арифметики. До виправлення: 20 помилок із 29 тестів. Після: 29/29.

Новий dashboardData.test.ts: 19/19 перевірок повної відповіді, від'ємного дня повернення, справжнього нуля, відсутніх/нечислових/нескінченних значень і неповних даних зарплати. Разом додано 48 тестів, не 48 незалежних дефектів.

Повні набори:

- server: 84 файли, 613 тестів;
- web: 137 файлів, 1297 тестів, один раніше пропущений тест залишено пропущеним;
- desktop: 123 файли, 1094 тести.

Усі ці прогони успішні. Пройшли typecheck server/web/desktop/API, web lint, server build і desktop-mode renderer build.

Ізольований UI smoke запускає справжній DashboardPage з контрольованими API, без доступу до магазину чи зовнішньої мережі. Пройшли дев'ять сценаріїв: відмова замість нуля, історична дата, помилка зарплати, старий desktop без повного звіту, неповна відповідь, пізній старий результат, справжній нуль, неповні рядки шиномонтажу, 390px мобільний екран з 20 працівниками та досяжним кінцем списку. Для мобільної перевірки підключено справжні Tailwind/analytics CSS. Це перевірка в браузері, а не на фізичному телефоні.

Перевірені більше 1000 чеків, чужий tenant, чернетка, скасоване повернення, архівна картка, дробова кількість, кілька рядків одного повернення й read-only транзакція. Контрольні суми повернень відповідають наявним локальним тестам пакета 10.

Упакований ASAR звірено з dist. Окремий Electron smoke із цього ASAR пройшов: дробовий залишок, повернення зі знижкою, ідемпотентність після відкриття та read-only recovery.
