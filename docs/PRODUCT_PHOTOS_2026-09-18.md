# Фото товарів — 18.09.2026

## Підтверджена причина

Read-only перевірка blackbox за 18.09: повторні `desktop:catalog:save-photo`
під роллю `cashier` завершувалися помилкою за 2–4 мс. Авторизація дозволяла
`save-product` касиру, але `save-photo` і `delete-photo` потрапляли під загальне
правило складських ролей без касира. Нові файли в локальному photos після
16.09 відсутні. Робочі товари, залишки та фото не змінювалися.

## Виправлено

- Save/delete photo мають ті самі ролі, що save-product. Видалення товарів,
  налаштування та інші адміністративні права касиру не розширені.
- Одна операція фото одночасно, включно з асинхронним збереженням картки.
  Помилка збереження не видається за успіх, старе фото лишається у картці.
- Форма чекає завершення додавання фото. Всі кнопки фото мають type=button.
  Зміна фото заблокована під час збереження товару.
- Фото в редакторі — частина чернетки; повідомлення явно просить зберегти
  картку. У перегляді товару фото зберігається автоматично з очікуванням.
- Прибрана оманлива багатофотогалерея: модель має тільки одне photo_url.
- Валідація файлу, межа 20 МБ, таймаут декодування, зрозуміла помилка
  непідтримуваного формату, біле тло прозорого PNG при перетворенні на JPEG.
- Завершення завантаження після виходу з картки не прикріплює фото іншому товару.

Web/desktop typecheck, web lint, desktop build та перевірка прав у compiled
модулі пройдені. Перевірено збереження/повторне відкриття/видалення посилання
на фото в окремій тестовій SQLite без зміни залишку.

EXE НЕ замінено: робоча програма відкрита, запитано закриття. Нових копій
програми не створено. Git push не виконувався. Перевірка реального додавання
фото касиром у встановленій збірці залишається після її оновлення.
