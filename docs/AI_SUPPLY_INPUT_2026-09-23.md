# 23.09.2026 — Товари в AI з буфера й Excel

## Що змінено

- У тому самому AI-помічнику: видимі кнопки «Excel / файл» та «Вставити».
  Підтримано Ctrl+V, перетягування, XLSX/XLS, CSV/TXT, існуючі фото/VIN.
- Таблиця автоматично вмикає розбір приходу, а не створення каталожних залишків.
  Одна таблиця → один перегляд → одна звичайна чернетка приходу з наявною оплатою.
- Зрозумілі колонки назви, кількості й закупівельної ціни читаються локально,
  без Gemini/інтернету. Читання Excel/CSV винесено з UI у Web Worker.
- Неструктурований текст передається AI лише після натискання «Надіслати».
  AI-відповідь перевіряється за тими самими строгими правилами перед підтвердженням.
- Не підмінюємо відсутню кількість одиницею, а нерозпізнану ціну нулем;
  нульова ціна допустима тільки якщо явно записана. Ціна продажу — за чинною
  таблицею націнок у звичайній локальній логіці приходу.
- Нулі на початку артикулів/штрихкодів збережено; числові клітинки Excel
  читаються за справжнім значенням, а не округленим виглядом. Не створюємо
  тимчасових артикулів на зразок XLS-sheet-row в парсері.
- Якщо кілька колонок одного типу, є некоректний рядок або неоднозначність,
  повертається зрозуміла помилка, а не мовчазний пропуск/вибір першої колонки.
  Невідомий другий аркуш не губиться: вся таблиця потребує AI-розбору.
- Дві таблиці одночасно або змішування таблиці й фото блокуються поясненням,
  щоб вкладення не перезаписувало інше. Буфер читається тільки після дії користувача.
- Старий окремий excelProductImport.ts прибрано після заміни єдиного виклику.
  Перевірка бізнес-даних, авторизація та idempotency локального приходу збережені.

## Межі

- Максимум 10 МБ на файл, 2 000 розпізнаних позицій, 1 млн символів тексту.
  Незрозуміла велика таблиця понад 160 тис. символів потребує виправлення
  заголовків або поділу користувачем; не розрізаємо цитовані CSV-рядки для AI.
- Розбір фото/довільного тексту потребує налаштованого AI й мережі.
  Реальний платний запит до Gemini у цій перевірці не виконувався.
- Для нової картки штрихкод як і раніше заповнюється у звичайній накладній;
  для наявної — використовуються дані знайденої картки. Проведення автоматично немає.
- Не змінювали залишки, рахунки чи накладні магазину. Два ПК і фізичний друк
  не належать до цієї перевірки. Автооновлювач не впроваджувався.

## Перевірки

- 632 web-тести (включно з 32 новими для таблиць), typecheck, lint.
- 24 локальні тести імпорту AI: зіставлення, чернетка, кількість, повтор, rollback.
- Реальний React/Chromium + реальний Web Worker: Excel без мережі, 98 шт,
  один підтверджений запис попри подвійний натиск, оплата у звичайній чернетці,
  Ctrl+V, кнопка буфера, помилкова кількість, два файли, довільний текст зі stub-AI.
- Реальний sandboxed Electron file:// + production worker: читання XLSX
  без API/мережі/робочої БД, точні артикул і кількість.
- Нові UI/renderer smoke-перевірки додано до майбутнього GitHub workflow.

курс записується в примітку чернетки. Змішані валюти блокуються.
