# Orders UX corrections — 2026-09-10

## Scope

Order entry, catalogue/analogue selection, status filters, cancellation and role-appropriate actions. No production orders, payments, stock or database schema were modified. Existing local-first repository and POS transaction boundaries remain unchanged.

## Implemented

- Ready, arrived and contacted orders share the ready queue; new/in-progress/ordered belong to work. Contact outcomes no longer hide a ready order in the supply filter.
- One cancellation flow: paid orders credit the customer; the cashier refunds through POS. Removed misleading immediate-refund/keep-in-shop alternatives.
- Cashier actions are not offered to managers. Warehouse rows do not offer supplier ordering; issuing outside POS is absent.
- One editable row layout for catalogue and manually entered parts. Supplier/date fields appear for backorders only. Markup is beside purchase price. Names are not truncated in search.
- Catalogue results show availability, location, barcode, price and expandable analogue choices with counts. Only visible results are queried, sequentially through the existing catalogue/analogue API; no inferred compatibility is written.
- Replacement preserves order quantity and agreed selling price, links the selected catalogue identity and updates purchase cost. Reselecting the same reserved product does not convert it into a backorder.
- Validate quantities and purchase/selling prices before saving, support decimal commas and grouping, warn about known shortages. Arrow quantity changes use a whole-unit step.
- Separate saving a draft from registering the customer order. Registration uses `new`, not supplier status `ordered`. Existing supply progress is not downgraded. No false success after activation failure; persisted documents open by ID instead of being created again.
- Session-local form backup is scoped by tenant, user and route. It preserves the original concurrency token, rows, customer/vehicle and in-progress fields across navigation/reload in the same session. It is not a database draft until explicitly saved. Successful save clears the backup; discarded unsaved changes do not delete an order.
- Documents moved into a secondary menu. Priced drafts reopen in the price-capable editor, handwritten notes keep their existing editor. Repeated view button removed from the mobile list.
- Existing payment total appears in the editor; source payments are not edited there. Removed obsolete dual-row-layout state.
- Protect delayed vehicle selection and markup calculation against applying to a different selected customer/row.
