# Допоміжні складські операції — 26.09.2026

## Обсяг і межі

Наступний етап погодженого технічного плану: ручні резерви, переміщення
між комірками, видача для потреб магазину, список і перегляд списань.
Жодних змін робочої БД, документів, цін або залишків. Усі перевірки —
на синтетичних даних. Наявні зміни інших етапів збережені.

## Виправлення

- Помилка завантаження резервів/переміщень/списань більше не виглядає
  як порожня база або нуль документів. Окрема помилка й повторне читання.
- Перегляд акта при помилці лишається за своєю адресою; немає хибного
  «акт не знайдено» й автоматичного переходу до списку через тимчасовий збій.
- Резерв, зняття резерву, переміщення та внутрішній відпуск мають синхронне
  блокування запису й перевірку актуальності відповіді. Після виходу зі
  сторінки відповідь не відкриває/закриває інше вікно й не перечитує старий список.
- Під час запису поля та закриття форми заблоковані. Помилка залишає
  введені значення; помилка оновлення списку після успішного запису
  не запускає запис повторно.
- Пошук товару/клієнта явно показує помилку й дає повторити читання.
  Внутрішній відпуск відкидає результати для видаленого рядка/закритої форми.
- У резерві показується qty_available, а не фізичний qty_on_hand під назвою
  «Доступно». Клієнта потрібно вибрати зі списку або очистити його пошук.
  Після успішного резерву нова форма отримує свіжий термін.
- Кількість у ручному резерві/відпуску приймає кому, до трьох десяткових знаків;
  відхиляє науковий запис, hex, зайві символи, надмірне число. Переміщення
  залишилося операцією всього фізичного залишку, без часткового обліку комірок.
- При зміні причини списань сторінка скидається одночасно з фільтром,
  без зайвого запиту старої сторінки. Новий відпуск не успадковує
  працівника й примітку скасованої форми.
- У warehouseApi видалено серверні шляхи запису резервів, переміщень,
  зняття резерву й списань. Без готового локального модуля запис відхиляється
  до створення журналу спроби. Читання веб-дзеркала збережене.
- Чинна durable-ідентичність не змінена: одночасний однаковий запит
  об'єднується, повтор того самого запиту після втрати відповіді
  використовує ту саму операцію. Новий успішний документ має нову операцію.

## Перевірки

- 868 web-тестів пройдено, один optional XLSX fixture пропущений.
  Нові: 20 тестів warehouseApi й 4 додаткові межі кількості.
- 758 desktop-тестів пройдено повністю, включно з атомарністю складських
  операцій, резервованим залишком, повтором після відкриття БД, rollback.
- Новий warehouse-action-ui-smoke: 16 груп сценаріїв реальних React-сторінок,
  подвійні дії, помилки читання/запису, дані після помилки, переходи
  під час запису, видалення рядка під час пошуку, фільтр/пагінація.
  Немає зовнішніх запитів і page errors. Включено до CI.
- Повторно пройдено writeoff-return-ui-smoke — невизначений результат,
  збереження чернетки, перевірка статусу без повторного списання/повернення.
- Web lint; production TypeScript/build; desktop test/production types.
- Electron/app.asar: product-detail-smoke й writeoff-return-smoke пройдені.
- Підготовка друку 1/1000/1 етикеток, offscreen, растровий чек, TSPL dry run,
  відновлення після аварії renderer — пройдені. Принтери не використовувались.

## Що ще не закрито цим етапом

Не оголошуємо завершеними весь аудит, фізичний тест двох ПК, зовнішні
резервні копії, реальну якість друку й канал автоматичних оновлень.
Для допоміжних складських дій перевірений повтор незміненого запиту;
окремий інтерфейс перевірки невизначеного результату перед зміною змісту
запиту (як у списань/повернень) — наступний кандидат для зміцнення.
