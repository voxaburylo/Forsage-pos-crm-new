# Пакет 92. Безпечний вихід із незбереженої картки

Продовження пакета 91: перевірено вихід з облікового запису та закриття
настільної програми після об'єднання карток і захисту незбережених форм.
Нових бізнес-функцій або кнопок не додано. Робоча база не відкривалася.

## Виявлені й виправлені дефекти

1. «Вийти» спочатку відкликало сеанс, тому форма могла зникнути раніше,
   ніж навігаційний захист запитував підтвердження. Перевірка форми тепер
   виконується до відкликання сеансу. Скасування не викликає auth API,
   не змінює права та не знімає захист чернетки. Під час збереження вихід
   блокується. Наявний захист від подвійного натискання збережено.
2. Команда завершення програми раніше могла почати зупиняти сервіси
   й закривати БД до того, як renderer відхилить закриття вікна. Тепер
   спочатку узгоджується закриття головного вікна; наявна процедура
   очікування активних команд, резервування та закриття БД запускається
   лише після його фактичного закриття. Допоміжні вікна друку не можуть
   залишити цю процедуру незапущеною.
3. Для звичайного закриття вікна додано внутрішній обмін підтвердженням
   між main і renderer. Одночасно дозволено тільки один запит. Помилка,
   невизначена відповідь або перевищення строку не дають згоди. Наявний
   beforeunload не вимикається; примусове знищення вікна не застосовується.
   Окремий шлях існуючого recovery-діалогу використовує тільки явний вибір
   «Закрити програму» й так само викликає звичайне закриття.
4. Незалежний огляд виявив крайовий випадок: підтвердження після timeout
   могло залишити дозвіл для наступного unload. Виправлено спільним
   незмінним deadline, який перевіряється до й після запиту, та коротким
   одноразовим дозволом renderer. Зміна стану форми й події input/change
   відкликають дозвіл; повторне редагування вже dirty-поля також захищено.

Auth SDK, область signOut, ролі та правила локального відкликання доступу
не змінювалися. За правилами навички Supabase зміна обмежена перевіркою
перед наявним auth-процесом. Семантику закриття звірено з офіційною
документацією [BrowserWindow.close](https://www.electronjs.org/docs/latest/api/browser-window#event-close),
[before-quit](https://www.electronjs.org/docs/latest/api/app#event-before-quit)
і [will-prevent-unload](https://www.electronjs.org/docs/latest/api/web-contents#event-will-prevent-unload).

- Web та desktop TypeScript, web lint і production web build: exit 0.
  Попередження про великі JS-частини збірки залишилося; не приховане.

Electron-фікстура використовує окремий тимчасовий профіль, блокує
зовнішню мережу й не запускає production main або БД магазину. Відповіді
confirm/alert і cleanup у ній синтетичні; це не ручний тест системного
діалогу й не повний packaged-app тест. Фікстура підтверджує життєвий цикл
вікна та спільний контролер, а прив'язку до production cleanup перевіряють
код і тести. Зовнішніх запитів і помилок сторінки в UI-перевірках немає.

Початкові невдалі запуски native-фікстури збережені для діагностики:
перші зупинялися через аргументи самого launcher, наступний — через
синхронний повторний quit тестового cleanup. Виправлення стосувалися
фікстури, ці запуски не видаються за підтверджені дефекти програми.
Попередження Electron про CSP стосується лише тестового Vite renderer;
production політика ним не перевірялася і не змінювалася.

## Стан випуску та наступний крок

Пакети 91–92 залишені в робочому дереві. HEAD — ca50b8c; commit і push
цього кроку не виконано. Попередні окремі правки постачальників і міграція
збережені, не скинуті та не включені до перевірок пакета 92.

Новий EXE не збирався й не встановлювався. Відкриту програму не закривали,
встановлений EXE й архів менеджера не змінювали: чинне побажання
користувача — працювати без заміни EXE. За попереднім контрольним записом
встановлена версія — пакет 87, підготовлений EXE пакета 89 не містить
змін 90–92. Web build не є встановленням настільного застосунку.

Наступний крок — чистий кандидат випуску 88–92 без незавершеного
постачальницького пакета, перевірки упаковки й сумісності. Потім —
установлення лише після завершення роботи користувача й дозволу на
заміну. Публікація окремо лишається невиконаною після попереднього
обмеження дозволів. Сервер, живий ШІ, фізичний друк і другий ПК цим
кроком не перевірені; робочі товари, залишки, ціни й платежі не змінено.
