# Відкриті чеки замість банера відновлення — 2026-09-15

## Причина та зміни
- При незакритому recoverCart старий код зупиняв оновлення копії. Окреме clearSavedCart також стирало копії всіх вкладок після оплати тільки однієї.
- Банер «Знайдено збережений кошик», кнопки відновлення/видалення копії та їхні обробники видалені.
- Залишається один набір відкритих чеків. При поверненні в касу живий стан має пріоритет; на новому запуску збережені вкладки відкриваються автоматично.
- Збереження підписане на зміни store. Серія сканів зберігається після паузи 180 мс, видалення товару/закриття вкладки — відразу. Перехід до меню та beforeunload зберігають свіжий стан.
- Закриття/оплата одного чека не стирає інших відкритих вкладок. Закриття касової зміни саме по собі не видаляє неоплачені товари.
- Операційний ID чека, активна вкладка, клієнт, замовлення, бонуси, знижка, нотатки й фото зберігаються. Захист від повторної оплати та фінансові повідомлення після невідомого результату платежу залишені.
- Ключі копії розділені за tenant/касиром. Старий загальний ключ переноситься тільки для підтвердженої поточної зміни та видаляється лише після запису заміни. Чужу/невизначену стару копію не видаляємо і не показуємо іншому касиру.

## Перевірки
- 16 тестів життєвого циклу відкритих чеків + 3 існуючі тести store — пройшли.
- Усі 535 тестів web та перевірка типів — пройшли.
- Ізольований headless Chrome, React StrictMode, реальний ReceiptPanel/store/controller: перенесення старої копії один раз; меню→каса; видалення; повторний запуск; збереження відкритого чека без зміни operation ID — пройшли. Робочу БД і продажі не використовували.
- У packaged renderer присутній новий ключ збереження, старого банера немає.
