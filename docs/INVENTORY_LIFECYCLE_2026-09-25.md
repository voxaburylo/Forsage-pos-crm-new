# Захист редагування та завершення ревізії — 25.09.2026

## Межі пакета

документи, залишки, платежі та принтери не змінювалися. Другий фізичний ПК

## Виправлено

1. Видалення позиції перевіряє саме відкриту версію рядка. Новий підрахунок
   не зникає через старий екран; повтор видалення вже прибраного рядка безпечний.
   ID позиції з іншої ревізії відхиляється.
2. Завершення застосовує лише переглянутий знімок. Зміна рядків, залишків,
   назви чи цін товару після відкриття підтвердження потребує повторної перевірки.
   Повтор успішного завершення не створює рухи залишків вдруге.
3. Початок, сканування, ручний підрахунок і видалення порожньої ревізії
   перевіряють її стан усередині транзакції, а не до блокування запису.
4. Назва, артикул, закупівельна та роздрібна ціни мають незбережену чернетку
   з початковим значенням. Помилка, оновлення даних, пагінація чи перезапуск
   сторінки не підмінюють введене. Перезапис новішого значення — тільки після
   явного звірення; відкидання чернетки не записує нічого в базу.
5. Якщо рядок прибрали іншою дією, його незбережені правки залишаються видимими
   окремо. Їх можна явно відкинути, щоб не отримати невидиме блокування завершення.
6. Усі редагування карток з ревізії проходять через один локальний метод із
   перевіркою початкових полів. Націнка додатково перевіряє закупівельну ціну.
   Масове редагування — одна транзакція: помилка пізнішої позиції відкочує
   увесь пакет, включно з чергою серверної копії. Залишки, фото, кроси,
   додаткові штрихкоди та інші поля не перезаписуються редактором ціни.
7. Прийняття ціни з цінника перевіряє початкову ціну; при помилці позначка
   розбіжності не зникає. Зберігаються перевірки прав працівника і магазину.
8. Для узгодженого читання введено readSnapshot: deferred SQLite-транзакція
   читає один WAL-знімок без захоплення блокування записувача. Звичайні записи
   як і раніше використовують BEGIN IMMEDIATE. Це перевірено двома з'єднаннями:
   незавершений запис не затримує читання; commit між SELECT не змішує версії.
