Цей пакет змінює лише тести, їхній ліміт часу в CI та документацію.

## Перша відмова GitHub

Verify 38104916866 для commit 1118041 завершився failure:
https://github.com/voxaburylo/Forsage-pos-crm-new/actions/runs/38104916866.

Typecheck і lint пройшли. Web: 1 577 успішних тестів і один optional skip.
Desktop: 2 272 успішних, один невдалий у 154 файлах.
Серверні тести, build і smoke цього GitHub run не виконувалися після відмови.

Єдина відмова: labelPrintConfirmation.test.ts, перевірка Normal=0.
spawnSync powershell.exe перевищив власний ліміт 10 000 мс.
У цьому тесті всі функції черги підставні, очікування черги замінене на
нуль секунд, принтеру нічого не надсилається.
Наступний аналогічний виклик зайняв 5 170 мс, наступні два — разом 606 мс.
Тому помилка підтверджує таймаут допоміжного процесу, а не неправильний
результат друку. Конкретна причина затримки першого процесу на runner
не встановлена; це не підстава називати реальний принтер несправним.

## Зміни тестового виконання

Два PowerShell-теста друку використовують спільний test-only helper:
один прихований процес, Unicode EncodedCommand, обмеження 30 секунд.
Окремий тест має 45 секунд, але subprocess сам завершується раніше.
Два позитивні сценарії етикетки розділені, щоб кожен тест чекав один процес.

Не допускаються автоматичні повтори або успіх лише за текстом OK:
помилка запуску, ETIMEDOUT, signal, nonzero/null exit, stderr та неповний
результат викликають відмову. Семантичні перевірки залишилися:
Normal=0 і черга без надрукованих сторінок не є успіхом;
порожня черга або підтверджений прогрес — успіх;
GDI зберігає всі пікселі на межі двох сторінок.

Перед виділенням PowerShell-фрагмента перевіряються обидві межі та
наявність production-очікування 15 секунд. Порожній фрагмент не може
мовчки пройти позитивні сценарії.

Ліміт усієї GitHub job збільшений із 25 до 45 хвилин, без зміни
таймаутів робочої програми. Підстава для запасу — послідовні тести:
локально desktop 225,56 с і server 489,50 с; GitHub desktop уже 462,56 с.
Далі потрібні server, build та всі native/UI smoke.
Це запобіжний бюджет за виміряною різницею швидкості, не твердження,
що первинний run був зупинений загальним лімітом: він упав на тесті раніше.

## Межі та наступний крок

Не оновлювали Electron, робочі драйвери, алгоритм друку, базу чи EXE.
Одиничний RunAsNode-збій 66 — окреме незакрите питання, не цей CI timeout.
Новий GitHub run має завершитися сам; локальна зелена перевірка не
підміняє його результат. Якщо буде наступна помилка, аналізувати саме її,
не повторювати весь цикл до випадкового зеленого результату.

До commit допускаються лише чотири файла тестів, часткова правка
timeout-minutes у verify.yml та протоколи 69–70. PostgreSQL job і всі
відкладені зміни постачальників залишаються поза цим випуском.
Повторна збірка EXE через test-only правки не потрібна.
