# ШІ після автоматичного денного входу — 29.09.2026

## Підтверджена причина

У локальному «чорному ящику» о 08:45:31 UTC записано ai-session-required.
Локальний вхід зберігався в зашифрованому денному дозволі, але Supabase
у desktop навмисно працював без browser persistence. Після завершення
процесу серверна сесія зникала. getSession не може відновити відсутні
облікові дані, хоча локальна каса залишається авторизованою.
Це збій перед розпізнаванням, а не доказ помилки OCR на конкретному фото.

## Виправлення

- Звичайний успішний онлайн-вхід або оновлення токена зберігає пару серверних
  токенів у тому самому зашифрованому Windows day lease, без пароля.
- Спочатку main перевіряє токен через зафіксований Auth endpoint.
  Перевіряються user id, довірений app_metadata tenant та стан доступу.
- Сховище прив'язане до локального працівника, магазину, fingerprint та
  початкового кінця дня Europe/Kyiv. Оновлення токена не продовжує строк.
- Повний вихід видаляє і локальний дозвіл, і серверний кеш. Новий вхід,
  інший працівник, змінений пароль, архівування та кінець дня не успадковують доступ.
- Запізніла відповідь після виходу/нового входу та старе паралельне збереження
  не можуть перезаписати нову сесію. Main додатково перевіряє живу сесію,
  а не лише async-контекст початкової команди.
- Відновлення використовує ізольований непостійний Auth client. Тільки
  перевірена сесія того самого працівника приєднується до основного клієнта.
- Ротація refresh credentials зберігається перед приєднанням.
- Локальна робота відкривається одразу й не чекає інтернету.
  Перший серверний запит також уміє дочекатися автоматичного відновлення.
- IPC приватний, лише після локального входу, не проксіюється на LAN-хост.
  Секрети не пишуться в localStorage чи діагностику.
- Нових кнопок або PIN-логіки не додано. Наявне ручне підключення лишається
  резервним способом для відсутніх/відкликаних серверних даних.

Вказівки Supabase застосовано до перевірки через Auth сервер і довірені
app_metadata, відокремлення локальних повноважень від серверних токенів,
недопущення витоку секретів та перевірок зміни акаунта.

## Межа підтвердження

Стара версія вже втратила серверні токени; новий код не може створити їх
без справжнього входу. Для поточного старого денного дозволу потрібен
один звичайний вихід з акаунта та вхід із паролем за наявності інтернету.
Не треба закривати касову зміну. Пароль користувач вводить сам.

Живий Gemini-розбір фото після цього входу ще не перевірений. Автотести
підтверджують авторизацію та локальний шлях, а не якість будь-якого фото.
Серверне відкликання доступу/невідповідний серверний пароль або відсутність
інтернету залишаються чесними причинами неможливості онлайн-розпізнавання.
