# Forsage — модуль подключения к сайту forsage-tires.com: ответ разработчику сайта

24.11.2026. Со стороны программы модуль готов по вашему контракту; ждёт шлюз `site-api` и ключ.

## Что сделано

- Сервер программы: `POST /api/v1/site-admin/gateway` с телом `{ action, params }`. Сервер добавляет `x-site-key`
  из переменной `SITE_API_KEY` (адрес шлюза — `SITE_API_URL`, по умолчанию ваш), тайм-аут 15 с.
  На шлюз уходит `{ ...params, action }`, ждём `{ ok, data }` или `{ ok:false, error }`.
- Разрешены только действия из контракта (28 штук). Поля `purchase_price`, `wholesale_price`, `min_price`,
  `buy_price`, `cost` не уходят ни в одном запросе.
- Каждое изменение пишется в журнал аудита программы.
- Раздел «Сайт»: заказы, клиенты, товары на сайте (описание, характеристики, скрыть, SEO, фото), категории,
  баннеры, акции, главная, страницы и статьи, отзывы, настройки, кнопка «Открыть сайт».
- Фото сжимает программа в WebP (full до 1000 px, thumb до 400 px) и кладёт по `upload_url` методом PUT.

## Что нужно уточнить в контракте

1. **Порядок фото.** Чтобы поменять порядок, программа вызывает `photos.attach` с полным списком в новом
   порядке. Нужно, чтобы `photos.attach` **заменял** список фото товара, а не добавлял к нему.
2. **Картинки баннеров и статей.** Программа вызывает `photos.upload_url { kind:"banner", count:1 }` и берёт
   из ответа `[0].full.upload_url` и `[0].full.public_url`. Подтвердите форму ответа для `kind:"banner"`.
3. **`upload_url`** должен принимать PUT из браузера (CORS) с `Content-Type: image/webp`.
4. **`orders.unseen_count`** программа спрашивает раз в 45 секунд, пока открыт раздел у владельца.
5. **`pages.upsert` для инфо-страниц:** программа передаёт `id`, `type`, `title`, `content`, `image_url`.
6. **Пустые значения** необязательных полей программа передаёт как `null`.

## Где программа отступила от задания и почему

1. **«Создать заказ в программе».** Заказ создаётся не записью в облачную `customer_orders`, а обычным путём
   программы: на кассе — в её базе, из веба — командой на кассу. Облако — только копия, запись в него мимо
   кассы потерялась бы. Товары с `program_product_id` идут позициями, остальное — текстом в примечании.
   Поля `source='website'` в программе нет: заказ отмечен текстом «Замовлення із сайту № …».
2. **Такой заказ виден в общем списке заказов программы.** Иначе его не увидит кассир, который выдаёт товар.
   Если владелец решит иначе — сделаем фильтр.
3. **Роль «Менеджер сайта» не добавлена.** По слову владельца раздел пока только у владельца.
4. **`notifyNewSiteOrder(order)`** есть на сервере и ничего не делает. Вызывать его будет фоновая проверка
   новых заказов, когда появится бот.

## Про чтение товаров сайтом напрямую из облака программы

В задании сайт сам читает `products` из базы программы. Обратите внимание: в этой таблице лежат закупочные,
оптовые и минимальные цены, а доступ `anon`/`authenticated` к ней закрыт. Читать её можно только служебным
ключом, который открывает всю базу программы, включая клиентов и продажи. Безопаснее читать каталог через
сервер программы — он уже готов и отдаёт только то, что можно показывать: `docs/SITE_API.md`
(`GET /api/v1/site/products` со своим ключом, изменения по `updated_since`, цены в копейках).
Решение — за владельцем.
