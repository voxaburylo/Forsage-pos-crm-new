# Пакет 99 — архівні товари не стирають історію документів

## Доведена причина

У локальному імпорті `upsertSaleItem` шукала лише невидалену картку товару.
Якщо товар архівували, рядок старого чека мовчки пропускався, хоча заголовок
і завершення імпорту зберігалися. Серверний bootstrap також повертав лише
активні картки, навіть коли включені документи посилалися на архівні.
Такий самий фільтр у локальному імпорті пропускав рядки старої ревізії.

Лише читанням підтверджено: три неповні чеки 1–2 липня мають на сервері
по одному рядку на 150 грн, усі пов'язані з однією архівною QA-карткою.
Це доказ наявності рядків у вебкопії, але не доказ трьох реальних продажів.
Історію магазину не відновлювали, не видаляли і не проводили повторно.

## Виправлення

- Локальний імпорт зберігає рядок чека з архівною карткою, її ID і збереженою
  собівартістю. Не активує товар і не створює повторного руху продажу.
- Якщо зазначено ID, але картки немає, імпорт відхиляється цілком: заголовки,
  рядки і курсор відкочуються. Помилка не видається за успішну неповну копію.
- Явний `product_id=null` залишається законною позицією вільної ціни:
  зберігаються опис і сума, не вигадується картка чи складський рух.
- Історичні рядки ревізії з архівними товарами теж зберігаються без
  повторного проведення та без зміни поточного залишку.
- Серверний owner bootstrap додає потрібні включеним документам архівні
  картки, з tenant-перевіркою, часовою межею та порціями до 80 ID.
  Браузерний активний каталог не змінений. Відсутня/чужа картка або неповна
  відповідь не підтверджуються як повна копія.

Немає міграції чи зміни схем, дозволів, кнопок, політики локальної головної
бази або зворотної синхронізації. Bootstrap як раніше має обмеження історії
30 днями для частини документів; цей пакет не перетворює його на повний архів.
Додавання архівних батьків сумісне зі старим клієнтом, але збереження рядків
архівних товарів потребує цього нового локального обробника.

## Перевірки

- 10 нових desktop сценаріїв: повна/часткова копія, повтор, архівна картка,
  оригінальна собівартість, невидимість у пошуку, незмінний залишок, відсутність
  повторного руху/черги, атомарна відмова, локально змінений чек, ревізія,
  явна вільна ціна без картки.
- 11 server сценаріїв: tenant, потрібний ID, tombstone, cursor, 161 посилання
  у трьох порціях, неправильна/дубльована відповідь; виконання фактичного
  `getBootstrapSnapshot` з підміненими джерелами для успіху та відмови.
- Повний server: 107 файлів, 1904/1904, 525,86 с. Server typecheck пройшов.
- Повний desktop до останнього уточнення явної вільної ціни: 178 файлів,
  2892/2892, 279,05 с. Після уточнення: 42 адресні тести і desktop typecheck
  пройшли. Остаточний повний desktop прогін входить до фінальної перевірки
  випуску; попередній результат не видається за цей наступний прогін.

Усі записи тестів — у тимчасових синтетичних базах. Робоча база і сервер
не змінені; фізичний друк не запускався. Виправлення механізму не означає
автоматичного виправлення давніх пошкоджених або тестових даних.
