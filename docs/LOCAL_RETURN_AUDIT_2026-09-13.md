За вказівкою власника Vercel та відновлення доступу відкладено. Робота лише
з локальним кодом і тимчасовими SQLite-базами. Робочі кількості, гроші,

## Відтворені й виправлені дефекти

1. Якщо спосіб відшкодування/дія зі складом не передані або null, документ
   записував стандартні cash/return_to_stock, але відповідні рухи не виконував.
   Тепер перевірка, документ, рухи та outbox використовують один нормалізований
   результат. Ідентичний повтор з явно вказаними стандартними значеннями
   повертає той самий документ і не проводить його вдруге.
2. Позначка повернення позиції замовлення враховувала видалені рядки/повернення.
   Тепер враховуються лише невидалені рядки невидаленого повернення того самого
   магазину та чека, як і в розрахунку доступної до повернення кількості.
3. Загальна знижка змішаного чека розподілялася без рядків «Вільна сума».
   У тесті товар 100 + інший рядок 900 зі знижкою 100 повертав 100 замість 90.
   Розподіл тепер охоплює всі рядки, але цей інтерфейс, як і раніше, повертає
   лише позиції з карткою. Чек із невідшкодованою вільною сумою не отримує
   неправдивий статус повного повернення.
4. Повернення послуги збільшувало її складську кількість. Гроші повертаються,
   але для is_service=1 складський залишок та рух товару не створюються.

## Перевірки

Новий набір returnConsistency.test.ts: 10 сценаріїв на реальній тимчасовій SQLite.
Початково відтворено 5 відмов для стандартних параметрів/видалених повернень,
потім ще 2 відмови для змішаного чека та послуги. Після виправлень цільові
сценарії й наявні orderCompletion пройшли (23 тести).

Додатково перевіряються: нестача готівки, явно вибране повернення через термінал
без оприбуткування, атомарний rollback при відмові outbox, повтор після
перезапуску. Дві реальні каси, фізичний ПРРО та друк не використовувалися.

Повний `pnpm verify` успішний: 458 web + 395 desktop + 272 server = 1 125 тестів,
перевірки типів (включно з API) та web lint. `pnpm desktop:smoke` успішний:
production renderer, компіляція desktop/preload й Electron на тимчасовій SQLite.
Попередження Vite про великі chunks/змішані imports залишаються; цей пакет їх
не усуває й не видає за доведену причину зависань. `git diff --check` без помилок.

## Відомі межі

Цей пакет не реалізує повернення довільної «вільної суми», не відновлює старі
помилкові повернення та не змінює стан доступу до веб-сервера. Перед випуском
EXE окремо перевірити сумісність черги вигрузки: сервер нового протоколу
дзеркала ще не розгорнутий. Не називати веб-копію актуальною лише через
успішні локальні тести.
